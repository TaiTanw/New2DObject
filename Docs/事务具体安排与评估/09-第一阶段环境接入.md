# 09 — 第一阶段第二步：环境能力与接入关系

本步按已确认的收敛范围整理环境接入：保留现有场景组件，统一登记和解除，由实体持有关系。没有新增全局环境管理器，没有加入云朵块、弹力块、跷跷板的专用接口或算法。

## 1. 实现的职责边界

| 结构 | 职能 | 不负责的内容 |
|---|---|---|
| 能力接口 | 提供现有参数/算法：主动移速修饰、持续速度、动态施力、地面响应、平台位移、墙滑 | 不代表几何接触，不直接维护受力者集合 |
| `BasicPhysicalObject` | 保留旧序列化字段与组件身份，承接 Unity 生命周期，转发通用登记 | 子类不再重写进入、退出、禁用清理 |
| `EnvironmentRegistration` | 可组合的接入辅助对象、旧状态容器的稳定来源键；源端反向索引及区域查询缓存 | 不保存速度/力数值，不决定碰撞响应 |
| `EntityEnvironmentContext` | 每个实体一份；拥有来源绑定、接入依据和已登记效果记录 | 不复制现有速度容器，不额外积分 |
| Context 内部 `Binding` | 记录一个来源的 Ground/Region/Explicit 接入依据，以及实际登记的效果 | 不单独暴露为一套公开管理系统 |
| `EntityEnvironmentFrame` | 相位 2 采样的支撑面阻力倍率、跳跃加成、平台位移 | 不合并丢弃持续效果的来源身份，不保存动态速度累计 |
| `PhysicsSolverMgr` | 原有实体接触计算 | 本步没有加入环境类型分支 |

没有单独引入 `EnvironmentEffectSpec`：目前三类登记效果可以直接从能力接口识别，绑定只需记录已登记内容。

`BasicPhysicalObject` 是兼容入口，而非能力接口的必要父类。其他 MonoBehaviour 可以独立实现所需能力并组合 `EnvironmentRegistration`；有持续作用时实现 `IEnvironmentSource`，并由自身生命周期转发清理/区域采样。单纯提供平台位移或墙滑参数无需注册环境源。

旧基类继续提供原有两项状态能力，包括中性值，以保留现有组件行为。新组件可以只实现一项能力；不存在的能力由接口缺席表示，数值零仍是有效参数。

## 2. 原有环境如何接入

| 组件 | 本步后的职责 |
|---|---|
| `IceGround` | 保留 `Idex/Odex/maxISpeed`、按受力者生成初始动态力、根据输入切换 apply/controlRecovery；三条重复生命周期删除 |
| `ForceField` | 保留 `add/maxSpeed` 和原初始化公式；区域采样与三类效果退出统一处理 |
| `pond` | 提供区域状态效果；无需自行写触发器进入/退出回调 |
| `BaseGround` | 旧地面参数及支撑接入兼容层，提供 `IGroundResponse` |
| `Taijie` | 增加 `IPlatformMotion`；自身相位 0 运动回调通过公共启停钩子注册/解除 |
| `Wall` | 提供 `IWallSlideSurface`；保留序列化参数，实体与逻辑层不再要求具体 Wall 类型 |

预制体脚本 GUID 和序列化字段保留。`Pond.prefab` 当前实际使用 `ForceField`，回归按实际组件执行，不按资源名称猜测。

## 3. 生命周期规则及明确变化

一个实体对同一来源只有一份效果登记。支撑、区域和兼容显式入口分别提供接入依据；最后一个依据移除才撤销效果。

- 支撑：实体每个相位 2 核对真实地面 Collider 上的有效环境源。原地禁用/重新启用不再依赖对象引用发生变化。
- 区域：源组件相位 2 使用同物体上所有启用的 Trigger Collider 采样重叠；按接收实体取并集。一个 Collider 离开而另一个仍重叠，不会提前退出。
- 区域查询考虑碰撞层矩阵、Collider 忽略关系以及 Rigidbody2D 存在条件。接收 Collider 位于子节点时，优先从 attachedRigidbody 定位实体。
- 源端禁用：公共入口解除所有反向绑定，动态力也统一停止控制，修复 ForceField 原禁用路径遗漏。
- 实体禁用：Context 解除全部环境来源，不再只通知当前/上一地面。
- Collider 禁用、删除、接收者重新启用：下一次区域采样重建实际关系，不要求 Unity 再发送 Enter/Exit 回调。
- 失效来源：实体相位 2 额外检查源的 Unity 生命周期。即使来源已销毁，也能安全撤销状态。
- 清理入口幂等，源和实体同时退出不会重复产生效果。
- 平台自身运动回调由 Start/OnDestroy 改为启用/禁用钩子：禁用时停止相位 0 更新并清零 Delta，重新启用时恢复。原 AudioSettings.dspTime 计时公式保留，不新增暂停计时语义。

区域接入由 Unity 触发回调改成相位 2 的重叠采样，是本轮明确的时序变化：源相位 2 与实体相位 2 的先后不影响三类状态在相位 3 被消费；所有相位 2 回调结束后才进入速度阶段。仍以物理步采样为准，不处理一个步长内经过但未被采样到的高速穿越。

当前一次性解除清理使用可复用缓冲区；常规区域采样使用复用列表/集合，不每帧创建 Collider 数组或新关系集合。查询成本随启用的区域 Collider 数量增长，本轮没有新增全局空间索引。

## 4. 速度与参数保留规则

- 主动移速修饰：仍按来源求和、限幅后应用 `1 + nowPhyNum`。
- 持续速度：仍按来源相加，不乘 EnvImpact。
- 动态施力：仍由相位 3 的原有 ForceData 公式计算，冰面输入控制不变。
- 环境退出：移除移速修饰与持续速度；动态力调用原 `RemoveForce`，转为 fadeAway，已经取得的速度继续由实体阻力衰减。
- 环境重新进入：仍沿用 `AddForce` 的旧规则，保留累计速度及旧初始化参数，仅恢复 apply。运行时参数刷新策略本轮未改，代码已标注。
- 冰面无移动能力分支、speedChangeNum 同时参与主动修饰和平衡速度的旧公式保留。
- 自身阻力仍在相位 1 按空中/着地重置，相位 2 只乘一次地面倍率；只有 fadeAway 使用该消退阻力。
- 表面参数与平台位移在相位 2 采样；平台相位 0 已完成位移更新，相位 3 把该位移加入 EntityMotionFrame 一次。
- 同一支撑 Collider 每类表面参数取首个有效能力提供者；持续效果允许多个源分别登记。不在本步增加表面优先级或混合材质规则。

## 5. 几何、墙滑与最终提交

几何数据增加真实 ground/left/right Collider。原 IPhyBaseI 引用暂保留供旧只读接口使用；能力解析通过真实 Collider 完成，不受第一个标记组件类型限制。

静墙与箱体分类仍依据实体身份，复合 Collider 可通过 attachedRigidbody 找到实体。无脚本地面仍可着地，无脚本墙仍可裁剪位移；没有墙滑能力的墙不自动允许墙滑。

墙滑只读属性原来返回 Wall 对象，消费方实际上只检查存在性；现在返回能力是否有效的布尔事实。物理侧通过 IWallSlideSurface 读取倍率，并检查 Unity 组件禁用/销毁，避免接口引用绕过 Unity 判空。

```text
相位 0：平台运动
相位 1：真实几何查询，重置自身基础阻力
相位 2：支撑/区域接入核对，支撑环境参数采样
相位 3：原速度计算 → EntityMotionFrame → 预测 AABB
相位 4：原接触偏置、T+1 动态接触施力
相位 5：基础位移 + 偏置 → 静墙裁剪 → 墙滑引用与编辑器观测 → MovePosition
```

MovePosition 仍是相位 5 的最后一条语句。运动快照中已标注的着地竖直环境速度问题保持原规则，本轮未顺便修正。

## 6. 验证入口与状态

编辑器菜单：`自定义工具/EPhy 验证环境接入（Edit Mode）`。

无界面入口：`EnvironmentIntegrationChecks.RunForBatch`。检查创建临时对象，使用实际冰面/力场/水域预制体、Unity Collider2D 查询和 BasicEntity 速度容器，不保存场景或修改预制体。报告写入忽略目录 `.utmp/EnvironmentValidation/`。

检查覆盖重复登记、原参数公式、退出尾效、重新进入参数规则、源和实体启停、多源叠加、复合 Collider、Collider 删除、独立能力接入、平台位移计入次数、Unity 接口引用失效。

2026-09-12 验证结果：

- Unity 2022.3.54f1c1 实际导入并编译运行时、编辑器程序集通过。
- Unity 无界面 Edit Mode 集成检查 **57 项通过**，结果为 `.utmp/EnvironmentValidation/checks.txt`，执行日志为 `unity-checks.log`。
- 去掉 UNITY_EDITOR / UNITY_EDITOR_WIN / UNITY_EDITOR_64 符号后的运行时代码独立编译通过；该项仍使用工程现有程序集引用，只验证条件编译边界，不是 Player 构建。
- 代码差异与既有序列化资源核对通过；本轮没有修改现有预制体、场景和脚本 GUID。

Edit Mode 检查显式调用框架启停清理入口，验证关系及真实物理查询，不模拟完整 Unity Play Mode 消息循环。推箱、墙滑、升降平台的 Play Mode 连续运行与手感验收仍待完成。

只读窗口增加有效环境来源数、移速修饰项、持续速度项、动态力项以及支撑参数。动态力项包含实体接触与已退出的尾效，因此不应与有效环境来源数简单要求相等；所有观测仍遵守 [05](./05-数据语义与调试约定.md) 的 EditorOnly 约定。

## 7. 后续边界

云朵块的允许嵌入与缓降、弹力块的反弹、跷跷板的联合受力/角运动，分别属于后续几何或物理响应算法。能力接口只保留接入位置，不表示这些算法已实现。

接触生命周期、共享力场速度协调、速度回写、多箱迭代仍在后续阶段。无全局环境管理器，无场景组件批量迁移，无接触算法替换。
