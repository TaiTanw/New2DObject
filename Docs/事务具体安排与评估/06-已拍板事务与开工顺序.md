## 0. 最新执行进展：第一阶段运动快照与环境接入

本轮已实现相位 3 的 `EntityMotionFrame`，使预测 AABB 与相位 5 提交复用 `plannedWorldDelta`。原着地分支省略竖直环境速度 `phyVSpeed` 的行为保持，并已在代码中标注待单独核对；新增结构职能、调用顺序与验证情况见 [08-第一阶段运动快照.md](./08-第一阶段运动快照.md)。

运动快照的运行时和编辑器程序集编译、定点数值检查已通过，Unity Play Mode 验收仍待完成。

随后已实施第一阶段第二步环境接入：复用 BasicPhysicalObject 外壳，能力接口与登记关系分离，实体 Context 统一拥有环境绑定；冰面/力场重复生命周期移除，区域改为相位 2 重叠采样。结构、明确的生命周期行为变化、验证入口和保留规则见 [09-第一阶段环境接入.md](./09-第一阶段环境接入.md)。接触速度算法、多箱迭代和原有 T+1 接触施力约定未在本步替换。

## 1. 当前故障与优先级

| 优先级 | 现象 | 现码证据 | 当前判断 |
|--------|------|----------|----------|
| **P0** | 持续推动单箱时仍有轻微抖动 | 已加入 `ContactSlop=0.002`，但接触候选仍严格要求预测 AABB 实际重叠；尚无 skin/释放阈值；动态力 link 又同时受重叠、相对闭合速度控制；Rigidbody2D 仍为 Dynamic | 当前首要故障。slop 只减少小穿入修正，尚未形成接触保持；必须先分辨 pair 开关、动态力开关和 Unity 二次修正各自贡献 |
| P1 | 贴 `wall (2)` 起跳，特定边缘位置在空中停顿一下 | `wall (2)` 位于 Layer 7；玩家 `groundLayer` 与 `wallLayer` 都是 Layer 6+7；地面/侧墙均使用 `distance=0` BoxCast；最终位置还会被 Dynamic 解算修正 | 高概率是墙顶边缘的接触分类切换，再叠加 Unity 角点修正；先补原始命中观测，不能先归因于跳跃 FSM |
| P1 | 斜坡上不能稳定连续推动两个物块 | 接触对仍只做一次冻结快照遍历；求得偏置后不更新解算器内预测位置。箱–箱已不再受 `ICanMove` 门控，并改走有向动态力，但同帧链式约束尚未闭环 | `ICanMove` 断点已消除；剩余问题是 N=1 接触链、斜坡轴选择以及 P0 抖动干扰 |

上述 `wall (2)` 项仍是高概率诊断，不是最终定因。需要记录每帧原始命中 Collider、法线、命中点和 `engineCorrection` 后再改行为。

### 1.1 当前 P0：持续推箱仍抖动

已经完成的部分：

- 位置修正改为 `max(rawDepth - slop, 0)`，不再把最终累计偏置统一截零。
- 水平施力使用双方总速度和相对闭合速度，不再依赖 `ICanMove`。
- 接触速度改走动态力容器；管理器保存 `source → receiver` 有向 link，并在退出时切换 `fadeAway`。
- 调试窗口可观察原始深度、实际修正深度、闭合速度、施力方向和目标速度。

仍可能导致抖动的四条链路：

1. **接触候选开关**：当前仍以 `v4.x > 0 && v4.y > 0` 为唯一候选条件。Unity 或自研偏置只要把双方分到零重叠之外，下一帧 pair 就消失；再次推进后又重新建立。
2. **动态力 link 开关**：link 只在“水平重叠 + 相对闭合超过阈值 + 单体速度朝接触面”时保留。双方速度趋同或短暂分离时会转为 `fadeAway`，重新闭合又恢复 `apply`。
3. **双重位置权威**：EPhy 提交 `MovePosition(requestedTarget)` 后，Dynamic 仍可能再次调整实体接触。若 `engineCorrection` 与 `solverOffset` 交替出现，属于两套响应共同作用。
4. **速度目标与位置偏置叠加**：普通推动由偏置产生位移，动态力又在下一帧提高箱体速度。若箱体总速度反复越过施力者速度，闭合条件会在正负之间切换。

P0 当前不是继续调小 `slop`，而是先取得逐物理帧证据，确认抖动主要发生在哪一条开关链路。P0 未关闭前，不接入正式推箱动画状态；否则物理抖动会直接变成动画闪烁。

## 2. 已拍板事务

### D1. 当前继续使用 Dynamic 混合模式

- EPhy 负责速度、玩法语义、实体接触和期望位移。
- Unity 2D 暂时负责静态世界最终非穿透。
- 不以 `useFullKinematicContacts` 代替碰撞响应。
- 静态扫掠、残嵌恢复和接触稳定未闭环前，不切换全 Kinematic。

### D2. 物理根节点不旋转

- 推箱解算目前只处理平移，Rigidbody2D/Collider2D 所在根节点冻结旋转。
- 表现子节点可以独立旋转，但只能表达装饰效果，不能暗示真实碰撞朝向。

### D3. 引入 skin 与 slop

- `skin` 用于接触候选和速度约束的提前感知。
- `slop` 用于容忍极小穿入，避免每帧纠正浮点噪声。
- 不能简单地把预测 AABB 永久膨胀后再把膨胀量作为位移推出。
- 当前已落地 `slop=0.002` 的代码常量，`skin` 与独立释放阈值尚未实现。
- 容差最终由解算器级配置统一持有，不散落在实体代码中；常量仅作为本轮定标起点。

推荐统一使用有符号间距：

```text
separation = centerDistance - (extentA + extentB)
separation < 0  表示穿入
separation = 0  表示理论接触
separation > 0  表示分离

contactCandidate = separation <= skin
penetration      = max(-separation, 0)
correction       = max(penetration - slop, 0) * correctionPercent
```

其中 `contactCandidate` 可参与法向速度判断；只有 `correction` 可以产生位置偏置。初始数值必须作为测试参数定标，不在算法方法内写死。

### D4. 两个及以上物块连续推动属于必需能力

- `N=1` 冻结快照不再视为可接受终态。
- 解算器应在自己的临时位置状态内迭代接触约束，最后一次性提交各实体总偏置。
- 迭代过程中不得反复调用 `MovePosition`，也不得让调试工具参与解算。
- 当前水平速度传播已改为相对闭合速度语义并移除 `ICanMove` 门控；后续多箱迭代必须保持该边界。

### D5. 调试工具只读

- 调试数据只允许从运行逻辑复制到编辑器快照。
- 工具不能写回速度、位置、接触状态或解算配置。
- 后续历史记录使用定长环形缓冲，不在物理帧持续刷 `Debug.Log`。

### D6. 表现层读取物理事实，不反向定义物理字段

- 不用 `displacementOffset != 0` 或动态力 `type == apply` 直接表示“正在推箱”。
- 管理器继续持有完整接触 pair/link；实体不复制单对象施力关系。
- 后续新增运行时只读接触摘要，提供目标、法线、进入速度、速度传递和最终运动结果。
- 表现层组合动作输入、接触事实、着地状态与最终运动结果，解析推动接触、有效推动和阻塞推动。
- 完整策略与验收见 [07-推箱交互事实与表现状态.md](./07-推箱交互事实与表现状态.md)。

## 4. 开工顺序

### 阶段 A：建立四个固定复现场景

1. 玩家贴 `wall (2)`，在墙顶边缘连续起跳。
2. 平地连续推动两箱和三箱。
3. 现有约 15° 斜坡上连续推动两箱。
4. 单箱抵住静态墙后持续推动。

每个场景至少记录：`fixedTick`、FSM 状态、原始 ground/left/right 命中对象、法线、预测接触对、有符号间距、请求位移、最终位置和 `engineCorrection`。

### 阶段 B（P0）：关闭持续推箱抖动

1. 以平地单箱持续推动作为唯一基准，暂不混入斜坡和箱链。
2. 逐物理帧记录 `rawDepth`、`correctionDepth`、接触 pair 是否存在、`closingSpeed`、有向施力是否成立、目标速度、箱体总速度、`solverOffset` 与 `engineCorrection`。
3. 先判断抖动来自“pair 消失/重建”“force link apply/fadeAway 切换”“箱体速度越过玩家”还是 Unity Dynamic 二次修正。
4. 若 pair 反复丢失，补 contact skin 与独立 release threshold；不得通过扩大最终偏置掩盖。
5. 若 link 反复切换，分离“持续接触事实”与“当前需要新增速度传递”两种状态。
6. 若 `engineCorrection` 与 EPhy 修正竞争，再按碰撞层临时关闭玩家–箱/箱–箱引擎响应做对照实验；静态墙响应保持。
7. P0 验收通过后，才进入推箱表现状态代码开发，见 [07](./07-推箱交互事实与表现状态.md)。

### 阶段 C：修墙顶边缘分类

1. 给只读快照补充原始几何命中信息。
2. 确认同一个 Collider 是否在相邻帧于 ground/wall 之间切换。
3. 将“感知查询”和“运动约束查询”继续分开；不得用扩大感知探针直接代替位移约束。
4. 若确认是角点法线不稳定，优先调整过滤与探针宽容区；不修改跳跃速度来掩盖停顿。

### 阶段 D：完成容差层

1. 保留当前逐接触 `ContactSlop`，新增解算器级 `contactSkin`、释放阈值与可选 `correctionPercent` 配置。
2. 接触候选使用 skin/释放阈值，位置偏置继续只使用扣除 slop 后的真实穿入。
3. 调试窗口同时显示 raw penetration 与 applied correction。
4. 先验证单箱平地、抵墙持续推动，再进入多箱测试。

### 阶段 E：升级接触链解算

1. 将预测样本复制为解算器本地 body state。
2. 每次约束迭代都更新本地预测中心，而不是重复使用原始 AABB。
3. 用相对法向速度判断接近/分离，并允许箱–箱传播运动意图。
4. 完成全部迭代后，向每个实体提交一次总 `displacementOffset`，并刷新跨帧动态接触力。
5. 检查遍历顺序反转后结果是否接近一致。

### 阶段 F：收紧混合权威

在阶段 A–E 通过后，观察实体接触上的 `engineCorrection`。只有当其长期接近零，才测试关闭 Unity 的玩家–箱/箱–箱动力学响应；墙和地面的 Dynamic 兜底不在同一轮移除。

## 5. 验收条件

- 平地单箱持续推动时，箱体位置和速度不出现可见周期性往返；接触 pair/link 不逐帧高频开关。
- `solverOffset` 与 `engineCorrection` 不形成方向相反的持续交替修正。
- `wall (2)` 边缘连续起跳不再出现超过一个 FixedUpdate 的非设计停顿。
- 平地三箱、斜坡两箱能够连续传递推动，箱体根节点角速度保持为零。
- 静置接触与持续推动时，接触候选不会逐帧高频成立/失效。
- 小于 slop 的穿入不产生位置修正；超过 slop 的修正量可在窗口中核对。
- 抵住无脚本静墙持续推动不穿墙，且不会因接触对偏置积累而逐步嵌入。
- 改变实体注册顺序后，多箱最终位置只允许出现容差范围内差异。

## 6. 本阶段不做

- 不切换全 Kinematic。
- 不把静态墙加入实体 AABB pair。
- 不实现箱体真实翻滚或角动力学。
- 不在修接触算法的同时批量重命名序列化数据类。
- 不通过调低跳跃速度、移动速度或扩大碰撞体掩盖边缘停顿。
- 不在 P0 接触稳定前，用物理噪声驱动正式推箱动画状态。
