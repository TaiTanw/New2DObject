## 1. 正式管线

```text
1 GeometricQuery          真实世界感知（静墙 / 地面）
2 PhyFunUpdate            支撑/区域环境接入核对，支撑环境参数采样
3 SpeedCalculation        动态力容器+状态速度+主动速度 → v_pre
   BuildMotionFrame       原有地面运动处理 + 平台 Delta → 本帧 plannedWorldDelta
   PositionPrediction     清零本帧 result；上报预测 AABB
4 ContactForSolution      AABB 接触对 → 本帧 displacementOffset
                          水平相对闭合 → 新增/刷新 source→receiver 动态力
                          新接触削弱符合方向的时间力/fadeAway 速度
                          旧有向关系退出 → RemoveForce/fadeAway
5 DisplacementCorrection  复用 plannedWorldDelta + displacementOffset
                          仅对「非 BasicEntity」静墙整轴裁剪
下一帧相位 3             ForceData.FixUpdate → phyHSpeed → 新预测
```

`Main.Awake` 调用 `PhysicsSolverMgr.Instance.Init()` 注册相位 4。

运动快照阶段已把基础位移统一为 `EntityMotionFrame.plannedWorldDelta`，预测 AABB 和相位 5 共用。着地分支省略 `phyVSpeed` 的现有提交规则已记录并保留，详见 [08-第一阶段运动快照.md](./08-第一阶段运动快照.md)。本次不改变下文的接触力 T+1 时序。

## 2. 数据结构

| 符号 | 位置 | 用途 |
|------|------|------|
| `EntityMotionFrame` | `Struct.cs` / `BasicEntity` | 相位 3 整体构建的只读基础运动快照，供预测和提交复用 |
| `PhysicalBoundingBox` | `Struct.cs` | `point` 预测中心、`size` **半长宽**、`myPhyBox` |
| `projectingArray` | `PhysicsSolverMgr` | 本帧快照；解算后 `Clear` |
| `EntitySolutionResult` | `Struct.cs` / `BasicEntity` | **本帧结果**：当前仅有 `displacementOffset` |
| `previous/currentContactForceLinks` | `PhysicsSolverMgr` | `source → receiver` 有向动态力生命周期 |
| `dynamicForceDic` | `BasicEntity` | 跨帧保存每个来源的 `ForceData.speedStacking` |
| `pendingAttenuations` | `PhysicsSolverMgr` | 同实体、同挤出方向每帧最多衰减一次 |

`PlayerPhysicsData.displacementBias` / `positionalEmbedding` 为旧草稿，**不走管线**。`secondOrderSpeed` 与 `AccumulateSecondOrderSpeed` 已删除；接触速度回到动态力容器，但由管理器统一维护，不恢复旧相位 5 单边边沿逻辑。

## 3. 位移挤出（本帧）

```text
v1 = a.point - b.point
v4 = (a.size+b.size) - abs(v1)     // X/Y 原始重叠深度
短轴挤出；weight = envImpact / sum
rawDepth        = 短轴重叠深度
correctionDepth = max(rawDepth - ContactSlop, 0)
双方 AccumulateDisplacementOffset，总和分离量 = correctionDepth
```

当前 `ContactSlop=0.002` 只控制位置修正；接触候选仍要求 `v4.x > 0 && v4.y > 0`，尚未加入 skin 与释放阈值。因此 slop 已降低零附近修正，但没有完成接触保持。最新进展及本轮验证边界见 [08](./08-第一阶段运动快照.md)，历史排查见 [06](./06-已拍板事务与开工顺序.md)。

当前实现为 N=1 冻快照累加。斜坡双箱已证明它只能作为基线；目标是有上限的解算器内迭代，仍禁止无界递归，见 [06](./06-已拍板事务与开工顺序.md)。

## 4. 速度施力（T+1）

当前最小实现只处理水平轴：

```text
separateSignA = sign(centerA.x - centerB.x)
closingSpeed  = -(velocityA.x - velocityB.x) * separateSignA
```

- `closingSpeed` 超过阈值后，再检查单体总速度是否与自身挤出方向异号。
- 源速度使用 `GetPlanarVelocity()`（主动+被动），不再使用 `ICanMove` 门控。
- 接收目标速度为 `sourceAxisSpeed * receiverWeight`。
- `SetOrUpdateDynamicForce` 刷新 `Force/balanceSpeed/recoverySpeed/type`，保留已累计的 `speedStacking`。
- 有向关系本帧未重新成立时，接收者对该来源执行 `RemoveForce`，进入 `fadeAway`。
- 新关系只对施力者的限时速度与 `fadeAway` 动态速度按方向衰减一次；主动速度、状态速度和仍在 `apply` 的持续力不改。

动态力在相位 4 写入容器，下一帧相位 3 由 `HUnderForce/FixUpdate` 计入 `phyHSpeed`。这是跨帧持续速度，不是每帧清空的二阶速度结果。

箱–箱已经可以按总速度形成下一跳有向力，但解算器仍为 N=1 冻结快照，所以同帧多箱约束和斜坡箱链尚未闭环。

## 5. 静墙

相位 1 检测仍可命中箱子（同 wallLayer）。相位 5 从真实命中 Collider / attachedRigidbody 识别 BasicEntity；只有未识别为实体的侧墙才进行静墙整轴裁剪，能力接口不参与箱体/静墙分类。
可推体重叠不再 `wordDelta.x=0`。
墙滑 `nowWallt` 在最终位移提交前由 `RefreshWallSlideSnapshot` 刷新，读取已解析墙面 Collider 上有效的 `IWallSlideSurface` 能力；`MovePosition` 保持为相位 5 回调的最后一步。环境接入与能力迁移见 [09](./09-第一阶段环境接入.md)。

当前暂不强制 Kinematic。实体保持 **Dynamic + gravityScale=0**：EPhy 计算期望位移，Unity 2D 暂时负责静态世界的最终非穿透。该模式不是最终定案；切换 Kinematic 前必须补齐静态扫掠、残嵌恢复和接触稳定。

箱体物理根节点冻结旋转，因为现有预测解算只处理平移。视觉 `image` 子节点可独立做装饰旋转，但不能用该旋转表达真实碰撞朝向。

## 6. 新增 API（相对开工前）

| API | 作用 |
|-----|------|
| `BasicEntity.EnvImpact` | 解算器读权重 |
| `BasicEntity.GetPlanarVelocity()` | 闭合/施力源速度 |
| `AccumulateDisplacementOffset` | 累加本帧接触位置修正 |
| `SetOrUpdateDynamicForce` | 刷新动态力参数并保留累计速度 |
| `AttenuateTransientContactSpeed` | 定向削弱时间力与 fadeAway 速度 |
| `RefreshWallSlideSnapshot()` | 替代旧二阶推墙里的墙滑快照 |
| `PhysicsSolverMgr.TryApplyHorizontalContactForce` | 私有；相对闭合与双方施力方向判断 |
| `PhysicsSolverMgr.Init` 由 `Main` 调用 | 注册相位 4 |
| `BasicEntity.DebugSnapshot` | 仅编辑器可用的只读实体快照，不参与解算 |
| `PhysicsSolverMgr.DebugContacts` | 仅编辑器可用的只读接触对快照 |

已移除：`SecondOrderPhyFun`、`NewUpdate`、`secondaryPressureDic`、`secondOrderSpeed`、`AccumulateSecondOrderSpeed`。
