# 08 — 第一阶段：运动快照、环境接入与唯一环境入口

当前新增进展：F_5.6 逻辑进一步优化已完成，见第 13 节；下述 F_5.1–F_5.5 内容保留各阶段历史情况。

本文汇总第一阶段 F_5.1–F_5.5 的已实施结果。F_5.1 统一预测与提交的基础位移；F_5.2 整理环境能力与登记关系；F_5.3 收敛为单环境宿主、多能力接口、单脚下来源；F_5.4 退出基类默认能力；F_5.5 把环境发现收到实体。接触生命周期、速度回写及多箱迭代仍属于后续工作。

## 1. 本次修改解决什么

原相位 3 用 `GetPlanarVelocity() * dt` 预测 AABB，相位 5 才进行地面切线处理和平台位移补偿。斜坡或移动平台上，两次计算使用的基础位移不同。

现在由实体在相位 3 构建一次 `EntityMotionFrame`，预测和提交复用其中的 `plannedWorldDelta`。原相位 5 的地面位移公式原样提取，接触力算法、静墙裁剪和 Dynamic 刚体模式保持现有实现。

改变的是预测所依据的基础运动。相同速度、地面及平台输入下，基础提交位移保持原规则；由于接触候选位置改变，实际接触偏置及随后运动结果可能随之变化。

## 2. 职能与数据归属

| 结构/方法 | 职能及生命周期 | 本次变化 |
|---|---|---|
| `PlayerPhysicsData` | 实体已有速度状态，由速度阶段和事件处理写入 | 字段及入账方式不变 |
| `EntityMotionFrame` | 实体持有的本帧未约束运动快照；相位 3 整体替换 | 只读值结构；正式运行保存 `plannedWorldDelta`，其余分量作为 EditorOnly 观测副本 |
| `BasicEntity.BuildMotionFrame` | 将已采样的速度、几何、平台及步长转换为快照 | 新增纯计算方法，从原相位 5 提取地面位移公式；不另行积分力或写 Unity 世界 |
| `PhysicalBoundingBox` | 向管理器上报预测中心、半长宽和实体引用 | 字段不变；中心改为当前 Collider 中心加 `plannedWorldDelta` |
| `EntitySolutionResult` | 相位 4 累加、本帧相位 5 消费的接触纠偏 | 仍只有 `displacementOffset`，不保存基础运动或跨帧速度 |
| `EntityPhysicsDebugSnapshot` | 编辑器只读观测结果 | 基础运动字段改从运行时运动快照复制，新增 `plannedWorldDelta` |
| `PlayerDataWindow` | 展示实体提供的快照 | 新增“预测/提交共用基础位移”，不参与运行时计算 |

`EntityMotionFrame` 放在现有 `Physics/Data/Struct.cs`，本轮没有迁移序列化字段或新增场景组件。

快照字段的区别：

| 字段 | 含义 |
|---|---|
| `debugFreeVelocity` | EditorOnly：速度结算后的原始合量，尚未应用地面位移规则 |
| `debugIntegratedVelocityDelta` | EditorOnly：原始 `freeVelocity * fixedDeltaTime` 的副本 |
| `debugMotionDelta` | EditorOnly：按原有地面规则处理后的实体位移副本，不含平台 |
| `debugPlatformDelta` | EditorOnly：本帧着地平台位移的副本；离地时为零 |
| `plannedWorldDelta` | `motionDelta + platformDelta`，在构造时合成一次 |

这些字段不是可以全部相加的速度/位移来源。速度积分和地面处理表达前后两种阶段；构建方法中的运行时局部量 `motionDelta + platformDelta` 组成基础位移，四个 debug 字段只供解释来源。格式约定见 [05 §4.1](./05-数据语义与调试约定.md#41-editoronly-命名与代码格式)。

## 3. 本帧调用顺序

```text
相位 1：GeometricQuery
相位 2：PhyFunUpdate
相位 3：SpeedCalculation
          → 原有水平/竖直速度计算（含上一帧接触动态力）
          → 采样地面法线、着地状态、fixedDeltaTime；读取相位 2 环境帧中的平台 Delta
          → BuildMotionFrame，整体替换实体 motionFrame
          → PositionPrediction
              清零本帧接触偏置
              Collider 中心 + motionFrame.plannedWorldDelta → 预测 AABB
相位 4：ContactForSolution
          → 本帧 displacementOffset
          → 原有下一帧接触动态力
相位 5：DisplacementCorrection
          → motionFrame.plannedWorldDelta + displacementOffset
          → 原有静墙裁剪
          → 刷新已解析的墙滑引用、记录编辑器观测值
          → 一次 MovePosition
下一帧：采集实际位置及 engineCorrection
```

相位 5 不再重新计算速度积分、斜坡切线或平台补偿；平台位移因此不会在预测和提交时重复相加。

`MovePosition` 保持为相位 5 回调的最后一条语句。墙滑引用来自此前已解析的静墙状态，更新放在提交前，不依赖提交后的真实几何；Unity 对移动请求的物理执行仍发生在后续模拟中。

“预测与提交一致”指二者的基础位移相同。接触纠偏、静墙裁剪和 Unity 后续修正仍会让最终落点不同于最初预测，不能要求二者最终位置始终相等。

现有水平接触施力仍读取 `GetPlanarVelocity()`，没有改为 `plannedWorldDelta / dt`。本轮没有实现新的接触速度算法。

## 4. 明确保留的竖直环境速度问题

`BuildMotionFrame` 的着地分支已用 TODO 注释标注以下事实：

```text
原始竖直合速度 = verticalSpeed + phyVSpeed

空中：motionDelta.y 使用原始竖直合速度

着地：先以 verticalSpeed * dt 重建竖直位移
      再加地面切线运动
      不加入 phyVSpeed

平台：platformDelta.y 另行加入
```

`verticalSpeed` 含自研重力和跳跃累计，不应按字段分组把它理解成纯主动目标。`phyVSpeed` 与平台 Y 位移来自不同链路，平台位移不能替代被省略的竖直环境速度。

本次既不补加 `phyVSpeed`，也不清零它；只让预测遵循现有提交规则。调试窗口仍能通过“速度积分位移”和“斜坡修正后位移”的差异观察该情况。

后续必须单独核对这些场景，再决定是否以及如何修改规则：

1. 平地静止时，正向竖直环境速度是否应使实体离地。
2. 平地静止时，负向竖直环境速度是否应被地面约束抵消。
3. 起跳首帧几何仍报告着地时，环境速度如何参与。
4. 斜坡切线具有 Y 分量时，如何区分地面运动与竖直外部速度。
5. 升降平台与竖直环境速度同时存在时，二者如何组合。

这些是待决定的玩法/运动约束规则，不以当前行为等价检查代替策略验收。

## 6. F_5.2：环境能力与登记关系

环境组件保留原有场景身份和具体参数，公共接入由 BasicPhysicalObject、EnvironmentRegistration 与 EntityEnvironmentContext 协作完成。

| 结构 | 当前职责 |
|---|---|
| 能力接口 | 提供移速修饰、持续速度、动态施力、地面响应、平台位移、墙滑等可读取能力 |
| BasicPhysicalObject | Unity 环境入口、Registration 持有、公共生命周期转发 |
| EnvironmentRegistration | 源端反向索引、区域采样缓存和稳定来源身份；不保存累计速度 |
| EntityEnvironmentContext | 每个实体一份绑定账本，记录接入依据和已登记效果 |
| EntityEnvironmentFrame | 相位 2 的支撑参数快照；不持有跨帧动态速度 |

冰面、力场、水域不再分别维护实体进入/退出名单。区域关系由相位 2 重叠采样建立，多个 Collider 对同一实体取并集；最后一个接入依据消失时，Context 按登记凭据撤销效果。动态力退出沿用 fadeAway，已经获得的速度仍归实体并继续衰减。

支撑参数、平台位移和墙滑能力均从真实 Collider 对应的环境入口读取。无脚本地面仍可提供几何支撑，无墙滑接口的墙仍可阻挡。平台 Delta 在相位 2 采样并随运动快照计入一次，MovePosition 仍是相位 5 最后一步。

## 7. F_5.3：唯一环境入口（已完成）

F_5.3 在 F_5.2 的关系结构上进一步收窄环境入口：

- BasicPhysicalObject 标记为不可重复挂载；编辑器验证工具可发现同一物体的重复环境宿主。
- EnvironmentCapabilities 先确定唯一 BasicPhysicalObject 宿主，再从同一组件读取多个能力接口。
- 同一组件实现多个能力时仍只有一个 EnvironmentRegistration 和一个来源身份。
- EntityEnvironmentContext 的 groundSource 改为本次相位 2 脚下来源的单引用；bindings 仍保留多来源关系，以支持脚下、区域和显式入口同时存在。
- 区域多 Collider 去重、来源/实体启停、Collider 删除、重新接入和动态尾效规则保持。

本单元没有新增环境管理器、入口父类或通用效果容器，也没有替换接触速度算法和物理相位。

验收结果：Unity Edit Mode 环境集成检查 60 项通过；运行时与编辑器程序集编译、单宿主多接口读取、重复宿主检查、平台位移计入次数和生命周期清理均已验证。Play Mode 连续手感、接触抖动、多箱迭代仍属于后续事务。

`RegisterEffects` 对已实现接口的零值也会登记。基类默认实现 `IMovementSpeedModifier` / `IStateVelocitySource`，因此所有环境入口都会写入移速修饰和持续速度。

|---|---|---|---|
| `IceGround` / `ICE.prefab` | 动态力、地面响应、移速修饰；公式读取 `speedChangeNum` | 持续速度（值为 0 仍登记） | `speedChangeNum=-0.5`，`slowingEffect=0.5`，`jumpHeightNum=-0.5` |

归属冻结（有异议再改）：

- `IceGround`：移速、持续速度、动态力、地面响应。
- `ForceField`：动态力；移速修饰留下（`Pond.prefab` 的 `-0.4`）。

- `Wall`：只留墙滑。仍继承 `BaseGround` 时，踩墙顶可能建立无效果的 Ground 绑定；不在本单元改继承。
- `BaseGround`：只留 `IGroundResponse`。`Delta` 仅 `Taijie` 经 `IPlatformMotion` 消费。
- `BasicPhysicalObject`：不再默认提供移速/持续速度。
- `pond` 类不删；不按类名猜测 `Pond.prefab`。

`Wall` 上未使用的攀爬/墙跳字段、`BaseGround.Delta` 公开暴露，本单元不处理。

## 14. F_5.7 / F_5.8 兼容层收敛（2026-09-22，进行到 `F_5.7_1`）

结构验证。环境类只回答能提供哪些物理量；Collider / Trigger 回答这些量以接触还是区域作用；地 / 墙由玩家碰撞点位判定。同一来源可同时提供贴墙摩擦和移速修饰；本帧用哪几个接口，在相位 1 点位事实之后由相位 2 选用。工程原则正文本轮不改。

### 需要收敛的兼容层

| 层 | 现码 | 目标 |
|---|---|---|
| `Wall : BaseGround` | 继承即带 `IGroundResponse`；踩墙顶会采默认阻力/起跳，并可能建空 Binding | 继承只声明量：`Wall` 只留 `IWallSlideSurface` |
| 来源集合不含侧面 | `currentSources` 只有脚下宿主 + Trigger；墙 Collider 只 `Find` 墙滑 | 侧面命中的宿主也进完整来源集合，才能消费该物体上的移速等持续量 |
| 空源仍绑定 | `pond`、纯墙作为入口被 `Attach` 后三类持续能力都没有 | 没有移速 / 持续速度 / 动态力则不建 Binding；采样仍可对脚下宿主读表面量 |
| `FindHost` 返回 `BasicPhysicalObject` | 几何发现绑在 Unity 外壳类型上 | 发现口返回 `IEnvironmentSource`（下一单元 `F_5.8`） |

不收敛：`speedChangeNum` 等旧序列化名；`IForceAction` / 动态力键；`pond` 类名；`Wall` 未用攀爬/墙跳字段；入口父类；全局环境管理器；接触算法；参数持续更新；监测点 / 深度。
