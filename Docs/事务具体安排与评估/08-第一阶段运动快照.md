## 1. F_5.1：预测与提交共用基础位移

相位 3 原来用速度乘步长预测，相位 5 才做地面切线和平台补偿，两次基础位移不一致。现在相位 3 用 `BuildMotionFrame` 做一次快照，预测和提交都用 `plannedWorldDelta`。接触力、静墙裁剪和 Dynamic 刚体保持原样。水平接触施力仍读平面速度，没有改成位移除以步长。

```text
相位 1：几何查询
相位 2：环境职能
相位 3：速度结算 → BuildMotionFrame → 用 plannedWorldDelta 预测
相位 4：接触纠偏与下一帧接触力
相位 5：plannedWorldDelta + 接触纠偏 → 静墙裁剪 → 一次 MovePosition
```

相位 5 不再重算地面切线或平台补偿。“一致”只指基础位移相同；接触纠偏、静墙和引擎修正仍会改变落点。

着地时竖直环境速度 `phyVSpeed` 仍不进入本帧位移，也没有被清零。空中才用竖直合速度；平台竖直位移另加。平地、起跳首帧、斜坡和升降平台如何组合，仍待单独决定，不把现状当成已验收规则。

编译通过，`BuildMotionFrame` 23 项检查通过。未做 Play Mode。相关：[04](./04-实体接触速度算法.md) · [05](./05-数据语义与调试约定.md) · [06](./06-已拍板事务与开工顺序.md)

## 6. F_5.2：环境能力与登记关系

场景组件保留自己的参数。公共接入由 `BasicPhysicalObject` 持有 `EnvironmentRegistration`，实体用 `EntityEnvironmentContext` 记账。能力接口提供移速、持续速度、动态力、地面响应、平台位移和墙滑。相位 2 采一帧支撑参数，不在快照里存跨帧速度。

区域重叠由实体采样，多个 Collider 对同一来源取并集。最后一个依据消失才按登记凭据撤销。动态力退出走尾效，已获得的速度留在实体上。无脚本表面仍可阻挡；没有对应接口就没有该效果。平台位移在相位 2 采样，并入运动快照一次。

#### 目标与现码落点

发现口对外返回 `IEnvironmentSource`，使 Context 用来源协议表达发现结果；场景组件仍由唯一 `BasicPhysicalObject` 提供身份与能力。本单元收窄类型依赖，不扩展发现范围。

| 位置 | 开工前 | 本单元目标 |
|---|---|---|
| `EntityEnvironmentFrame.cs / EnvironmentCapabilities.FindHost` | 返回 `BasicPhysicalObject`，从 Collider 同物体获取唯一宿主 | 返回 `IEnvironmentSource`；方法内部仍取 `BasicPhysicalObject` 并保留有效性过滤 |
| `EnvironmentCapabilities.Find<T>` | 将同一宿主转换为能力接口 | 保持泛型签名与同宿主规则，从来源接口查询能力 |
| `EntityEnvironmentContext.RefreshEnvironment` | `groundHost` 局部变量为具体宿主类型 | 局部变量改为来源接口，传给事实收集和脚下采样 |
| `CollectSources` | 脚下参数及区域 `host` 局部变量为具体类型，再匹配来源接口 | 参数和局部变量统一为来源接口，去掉多余的同接口模式匹配 |
| `SampleGroundFrame` | 参数为具体宿主类型，读取两类表面能力 | 参数改为来源接口；仍只从该来源读取 `IGroundResponse` / `IPlatformMotion` |

当前脚本调用者只有 Context 两处发现与 `Find<T>` 的转发；`EnvironmentRegistration.Source` 已是 `IEnvironmentSource`，本单元不改注册表结构。

#### 范围与边界

- `FindHost` 保留 Collider 空、禁用、层级失活检查，以及宿主存活和启用检查；继续只用 Collider 同物体的 `GetComponent<BasicPhysicalObject>()`。不查父物体、子物体、附着刚体，也不从其它组件拼接能力。
- `BasicPhysicalObject`、`DisallowMultipleComponent`、来源身份与 `ReleaseAll` 生命周期保持；`FindEntity` 和通用 `IsActive(object)` 不改。接口局部变量的空判断只用于接收经过 `FindHost` 过滤后的结果，不替代宿主的 Unity 生命周期判断。
- Context 的 `CollectSources → SynchronizeSources → SampleGroundFrame` 顺序、完整来源去重、三类持续能力判断、绑定进出与速度尾效保持；脚下缺席时仍采样默认 1 / 0 / 零位移。
- 点位选择、Trigger 过滤、墙滑/墙跳及物理相位均不变；不增加纯 C# 来源生产类、手动注入口、适配层或管理器。纯 C# 来源检查仅验证已有注册表协议，不表示 Collider 可以发现任意纯 C# 对象。
- 预计仅修改两个运行时文件中的类型声明及重复判断，不新增类型或方法，不修改场景、预制体和序列化字段。编辑器检查按验收缺口补充。
