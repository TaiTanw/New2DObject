# 07 — 推箱交互事实与表现状态

> 状态：开发策略已拍板，代码尚未开工。
> 前置条件：先关闭 [06](./06-已拍板事务与开工顺序.md) 中“持续推箱仍抖动”的 P0。

---

## 1. 结论

表现层缺少推箱动画依据，不能通过以下任一数据单独补齐：

- `EntitySolutionResult.displacementOffset`：它是对称的几何修正，不表示谁推谁。
- 动态 `AddForce` 关系：它只表示速度传递，无法覆盖低速偏置推动和稳定贴合。
- 为动画新增 `isPushingAnimation`：它把表现决策倒灌进物理层，并且无法表达阻塞推动。

正确边界是：

> 物理层公开稳定、只读的接触事实；行为/表现层结合动作输入、几何状态和运动结果解析推动意图与动画。

物理层可以提供一个暂时只被表现层消费的数据，只要它表达的是真实物理事实，而不是“播放哪个动画”的指令。

---

## 2. 生命周期与数据分层

### 2.1 持续动作不等于必须保存永久布尔

“正在推箱”可以由连续物理帧重复成立的可推接触事实与动作输入共同表达：

```text
FixedTick N     可推接触成立 + 输入朝向接触面
FixedTick N+1   可推接触成立 + 输入朝向接触面
FixedTick N+2   可推接触成立 + 输入朝向接触面
                 ↓
表现层观察为持续推箱
```

物理快照每帧重建，与动作在时间上持续并不冲突。动画起手、退出延迟和防闪烁计时属于表现状态机，不应写入物理解算数据。

### 2.2 三类数据继续分开

| 数据 | 生命周期 | 职责 |
|------|----------|------|
| `PlayerPhysicsData` | 跨帧运动状态 | 主动/被动速度及持续环境影响 |
| `EntitySolutionResult` | 当前物理帧 | 接触解算器输出；当前仅有位置修正 |
| 推箱接触事实 | 每个物理帧重建 | 接触对象、方向、进入速度、速度传递与最终移动结果 |

`displacementOffset` 不进入 `PlayerPhysicsData`。如果后续统一命名，建议将 `EntitySolutionResult` 扩成 `EntityFramePhysicsResult`，而不是把帧结果嵌入持续运动状态。

---

## 3. 为什么现有数据不能等价为“正在推”

### 3.1 位移偏置只回答几何恢复

`displacementOffset` 可能来自生成重叠、平台挤压、其他箱体推挤或 Y 轴接触。双方都会获得偏置；重叠进入 `slop` 后，持续贴推时偏置还可能为零。因此它不能回答：

- 接触对象是否为可推物；
- 谁是主动一方；
- 玩家是否仍朝接触面输入；
- 目标是否实际移动。

### 3.2 动态力关系只回答速度传递

管理器保存 `source → receiver` 有向关系，是为了刷新和退出动态力。该关系对解算是必需的，但不等同于推箱动作：

- 普通低速推动可以主要由位置偏置完成；
- 双方同速后相对闭合速度为零，速度传递可能退出，但接触意图仍持续；
- 目标抵墙时仍可能有推动意图，却没有有效运动。

因此实体不需要复制管理器的完整施力容器；表现层也不能直接读取该容器作为动画开关。

---

## 4. 推箱语义拆分

“推箱”至少包含四个需要分开表达或推导的概念：

| 概念 | 所属层与最小判断 | 用途 |
|------|------------------|------|
| 可推接触 | 物理事实：接触目标具备可推动能力，并有明确接触法线 | 推动判定的物理前提 |
| 推动意图 | 行为/表现推导：主动输入朝向可推接触面 | 推箱姿势、用力表现 |
| 速度传递 | 物理事实：本帧建立或刷新 `source → receiver` 动态力 | 物理调试、撞击反馈 |
| 有效推动 | 运动结果：目标最终沿推动方向产生足够位移 | 行走推箱动画、移动音效 |

箱体抵住墙时建议同时允许：

```text
可推接触 = true
推动意图 = true
有效推动 = false
```

这三项组合可推导出“阻塞推动”。表现层可以自由选择“继续播放用力顶住”或“停在阻塞姿势”；物理层不替动画层拍板两者是否使用同一动画。

---

## 5. 物理层需要公开的关键事实

不新增表现命名布尔；优先提供可组合的数据：

```csharp
// 结构示意，不代表已经落地的最终命名。
public struct ContactInteractionResult
{
    public BasicEntity target;
    // 约定为当前实体远离 target 的单位法线，避免调用方二次猜测正负号。
    public Vector2 separationNormal;
    public float inwardSpeed;
    public float transferredTargetSpeed;
}
```

后续还可在位移阶段补充：

```csharp
public Vector2 appliedDelta;
```

表现层据此结合现有只读数据：

```text
ReadOnly_ActionData.onMove
+ 接触目标是否具备可推动能力
+ separationNormal
+ ReadOnly_GeometryPhysicsData.isGrounded
+ 目标 appliedDelta（若要区分有效/阻塞）
→ 推箱动画状态
```

可推动目标应最终由能力语义（例如 `IPushable`）表达，不建议让表现层长期硬编码 `PhysicalBox` 具体类型。

---

## 6. 数据所有权与只读出口

### 6.1 完整关系由管理器持有

管理器继续作为接触对和有向施力关系的唯一权威。实体不再恢复单对象的 `nowForceThing/lastForceThing`，因为单引用无法表达多箱、多方向或同帧多个接触。

### 6.2 实体只保留本帧摘要

推荐由管理器在相位 4 写入实体的本帧接触摘要，实体向上层提供只读包装。摘要可以选择主要接触对象，但不能反过来参与接触解算。

```text
PhysicsSolverMgr 完整 pair/link
        ↓ 汇总
BasicEntity 本帧只读 ContactInteractionResult
        ↓
PresentationLayer / FSM 解析
```

如果一个实体同帧存在多个候选，主要接触应按主动方向、目标是否可推和进入速度排序；不能依赖 pair 遍历顺序。

### 6.3 读取时序

- 相位 3 开始新物理帧，重置上一帧接触摘要。
- 相位 4 写入预测接触事实。
- 相位 5 写入最终请求/实际运动结果。
- `PresentationLayer.Update` 读取最近一次已经完成的物理帧快照。

表现层跨多个渲染帧读取同一快照是允许的；不得在 `Update` 中主动清除物理结果。

---

## 7. 当前真实缺口

当前不是缺少一个动画布尔，而是缺少两层正式输出：

1. **运行时接触读模型**：管理器已经算出 pair/link，但除编辑器调试快照外，没有供玩法与表现读取的稳定接口。
2. **方向自由度/运动结果**：实体–实体接触在相位 4 解算，静墙整轴裁剪在相位 5 才发生。管理器暂时不能完整回答接收箱沿推动方向是否最终可移动。

第二项同时影响推箱物理正确性、箱链传播和阻塞反馈，不应只为动画做局部猜测。短期可以读取相位 5 的 `appliedDelta` 判断有效推动；长期应让静态约束或方向自由度参与统一解算。

## 8. 实施顺序

### P0 前置：先解决持续推箱抖动

接触事实若仍在相邻物理帧反复成立/失效，任何推箱动画状态都会跟着闪烁。必须先完成 [06](./06-已拍板事务与开工顺序.md) 的 P0 接触稳定闭环。

### P1：建立运行时接触事实

1. 确定可推动能力接口或目标分类。
2. 由管理器生成本帧接触事实，不读取 `displacementOffset` 反推。
3. 实体只保存只读摘要，不复制完整有向施力容器。
4. 暂时只提供推动接触、方向和速度传递信息。

### P2：补最终运动结果

1. 相位 5 记录本实体最终 `appliedDelta`。
2. 建立目标沿推动方向是否实际移动的只读结果。
3. 表现层区分可推接触、推动意图、有效推动和阻塞推动。

### P3：表现层接入

1. `PresentationLayer` 组合动作输入、接触事实、着地和最终运动结果。
2. 动画起停滞回只存在于表现层。
3. 物理快照不得引用 Animator 参数或动画状态枚举。

---

## 9. 验收条件

- 低速仅靠位置偏置推动时，仍能稳定识别可推接触。
- 双方速度趋同后，持续按向箱体不会丢失可推接触和推动意图。
- 玩家被箱体反向挤出时，不会误识别为玩家主动推箱。
- 普通墙接触不识别为推箱。
- 箱体抵墙时能区分可推接触、推动意图与有效推动。
- 动画层不读取或修改管理器的内部 `HashSet<ContactForceLink>`。
- 调试窗口与运行时只读结果不得回写物理解算。

---

## 本阶段不做

- 不通过 `displacementOffset != 0` 直接播放推箱动画。
- 不通过动态力是否为 `apply` 直接播放推箱动画。
- 不在物理层增加 Animator 参数或 `isPushingAnimation`。
- 不为了单个动画恢复旧的单对象施力字段。
- 不在 P0 抖动未关闭前接入正式推箱动画状态。
