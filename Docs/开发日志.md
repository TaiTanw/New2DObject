## K001：被动水平速度与统一制动

2026-10-17 · 已实现并通过自动验证；人工场景与手感仍待验收。

### 人工发现与确认

1. 开发者从旧力枚举简化后的行为入手，追问“箱子被推出后，惯性距离如何受地面摩擦控制”。沿代码核对，发现自身制动受 `!effectState.HasDynamicForces` 限制：只要还有动态来源，即使施力为零，也会跳过自身阻力。
2. 继续追问后，开发者指出动态受力与制动分散在两处，且最终物理数据 `phyData` 同时承载中间运算，语义不清。提出将自身阻力传入 `CalculateDynamicVelocityDelta`，在同一处完成计算。
3. 最终确认：`balanceSpeed` 只表示来源施加阶段的上限，随后制动使最终速度略低可以接受；冰面仅提供属性及受控复原入口，离开后使用自身阻力，不增加专属制动。

### 采用与放弃

- **采用最小调整。** 从刚体实际速度分离出本步被动水平速度，用局部变量承载计算；多个来源依次作用后，再统一执行一次自身制动，返回速度增量。自身阻力先应用地面倍率，环境系数与步长各计算一次；趋零减速不越过零。
- **保留受控复原。** 它是来源提供的额外减速，可与自身阻力共同生效；来源退出只撤销控制，实际惯性由 Unity 保存。移除外层条件及整段旧制动，避免重复计算。
- **不恢复旧消退枚举及独立速度容器。** 开发者认为，这会重新引入容器预估速度与 Unity 撞墙后实际速度的同步成本，本次没有必要。也不为施加上限补偿随后制动，不新增跨帧速度状态。

### 成果与后续

运行时代码调整集中于 [BasicEntity](../Assets/Script/Framworker/Function/Physics/Component/PlayerOBJ/base/BasicEntity.cs) 与 [EntityEffectState](../Assets/Script/Framworker/Function/Physics/Data/EntityEffectState.cs)，保持主动移动、重力和框架时序。本次制动专项 27 项、环境接入 161 项、移动与动画迁移 73 项、实际场景推箱 4 项验证通过，覆盖来源存在时制动、冰面退出及撞墙后惯性不复活。

后续先完成人工场景与手感验收；类似整理可继续核对物理输出与中间计算的边界、受力职责是否集中，再决定是否需要改动，不据此扩展新功能。

## K002：水平目标与公开结果分离，水平子类重写返回目标值（单元 1）

2026-10-21 · 单元 1 已实现并通过自动验证。

开发者沿相位 5 输出继续追问，发现 `horizontalSpeed` 在父子类间先后表示主动目标、自身水平合计和模拟后分量。确认采用分单元整理：保留基本计算与子类钩子，先让水平目标退出公共数据工作区；不为动画恢复旧主／被动速度容器。

本单元链路改为：`HActiveSpeedOperation()` 返回水平目标 → 基类计算主动分量 → 局部 `plannedOwnVelocityX` 合成自身水平 → 地形处理并提交 → 相位 5 沿用原输出。目标计算后消费动作事件的位置不变，随后仍处理重力与竖直规则。

| 项目 | 本轮增减与语义 |
|---|---|
| `HActiveSpeedOperation` | 返回类型由 `void` 改为 `float`；本工程覆盖实现和观测夹具已同步 |
| `targetHorizontalSpeed / plannedOwnVelocityX` | 本步局部值，分别承载目标、自身水平合计；无新增跨帧字段 |
| `HasHorizontalDrive / activeHorizontalVelocity` | 保留；没有驱动与目标为零仍是不同情况 |
| `horizontalSpeed` | 字段保留；普通运动相位 3 不再读写它。相位 5、飞行直接发布及显式刷新仍沿用原语义 |

新增测试位于 `Assets/Script/Tesk/Editor/HorizontalDriveTargetChecks.cs`：21 项专项通过，覆盖旧输出不干扰计算、零目标／无驱动、反向保留惯性、地面修饰、坡面投影、撞墙及事件顺序。Unity 同次回归中，环境 161 项、移动与动画 73 项、统一制动 27 项通过；进程退出码 0。离线运行时代码和编辑器代码编译也通过。

下一步仅在确认后处理竖直候选工作数据；状态／限时速度的返回值与公开输出整理仍属后续单元。本轮不改竖直、效果容器和表现层语义。

## K003：本步候选速度与公开结果分离（单元 2）

2026-10-21 · 已实现，编译与行为等价回归通过。本项仅整理数据传递，不设额外人工手感验收门槛。

开发者指出父子类借同一物理数据对象反复改写，目标、计算过程与最终结果难以区分，确认保留计算钩子并分单元处理。完成水平目标返回值后，本单元让自身竖直计算也退出公开结果对象；不恢复旧主／被动累计速度容器。

链路为：从实际速度初始化局部候选 → 汇总效果及被动水平计算 → 返回水平目标 → 动作事件修改候选 → 合入主动水平分量 → 重力 → 竖直规则 → 与附加命令合成提交 → 相位 5 沿用原回读。事件仍在目标之后、重力之前消费；墙跳限时命令仍晚于本步效果汇总，下一步才计入。

| 项目 | 本轮增减与语义 |
|---|---|
| `MotionStep.OwnVelocity` | 新增嵌套工作结构及其中一个 `Vector2` 字段；实例仅在本次相位 3 调用中存在，始终表示自身候选速度，不新增实体跨帧状态 |
| `plannedOwnVelocityX` | 局部量移入 `step.OwnVelocity.x`，水平公式及驱动判断不变 |
| `PhyEventUpdate` | 改为基类显式调用的 `ref MotionStep` 钩子；子类在原先后位置消费跳跃、墙跳、松跳 |
| `VUnderForce / VActiveSpeedOperation / VerticalTransmission` | 显式传递同一工作值，重力及墙滑、游泳、水面规则修改候选 Y，不再改公开 `verticalSpeed` |
| `PlayerPhysicsData`、跨帧分量、相位 5 输出 | 字段均保留。普通相位 3 不再读写公开自身水平／竖直速度；飞行直接发布、显式刷新清零仍保留。效果汇总字段留待单元 3，表现层沿用原读取方式 |

新增 `Assets/Script/Tesk/Editor/VerticalMotionStepChecks.cs`，36 项专项通过：包括公开输出隔离、钩子顺序、着地与顶头裁剪、真实角色跳跃／松跳、墙跳生效步次、游泳及水面平台补偿。连同环境 161 项、移动动画 73 项、统一制动 27 项、水平目标 21 项，共 318 项通过；Unity 退出码 0，离线运行时代码与编辑器代码编译通过。

## K004：状态／限时速度与公开结果分离（单元 3）

2026-10-21 · 已实现，编译与自动等价回归通过。

开发者确认分单元整理，并指出前两单元编辑器代码增量偏大。本轮只迁移附加速度的计算入口，复用现有夹具补关键边界，不再新增测试文件或独立验证框架。

链路改为：效果容器汇总状态／有效限时速度并返回 → `step.StateVelocity` → 下坡计算、水面补偿及最终附加命令合成 → 相位 5 沿用原输出。平台位移仍单独换算速度；效果汇总仍早于动作事件，墙跳新登记的限时命令仍在下一步汇总。

| 项目 | 本轮增减与语义 |
|---|---|
| `UpdatePassiveSpeed(PlayerPhysicsData)` | 替换为返回 `Vector2` 的 `CalculateStateVelocity()`；不再写公开物理数据，累加顺序和过期清理保持 |
| `MotionStep.StateVelocity` | 新增本步工作字段，含状态速度与有效限时 X；不含平台、坡面，不新增实体跨帧状态 |
| `phyHSpeed / phyVSpeed` | 字段保留；普通相位 3 不再读写，继续在相位 5 发布原有分量结果。飞行直接发布和显式刷新清零保留 |
| `nowPhyNum` 与来源容器 | 保留原移速参数汇总接口，状态字典、限时列表和来源登记规则不变 |

既有本步运动专项由 36 项扩充为 47 项，验证旧附加输出隔离、状态／限时合成、环境系数、撤源与到期、水面补偿和墙跳步次。连同环境 161 项、移动动画 73 项、制动 27 项、水平目标 21 项，共 329 项通过，Unity 退出码 0；离线运行时代码与编辑器代码编译通过。

公开结果字段的删改仍留给单元 4，本轮保持表现层接口及动画判断方式。
