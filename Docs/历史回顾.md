## 从单边推箱到预测接触（原 01–04）

旧方案由实体在位移阶段判断是否推另一个对象，难以表达成对挤出和多箱关系。后来由 `PhysicsSolverMgr` 集中读取预测 AABB：本帧累加双方位移偏置，有向动态力在后续速度阶段消费，删除旧相位 5 的单边推箱施力路径。

截至 F5 完成的基线：

| 项目 | 已有实现与边界 |
|---|---|
| 预测 | AABB 中心来自实体本帧运动快照，size 表示半长宽 |
| 位置修正 | 预测重叠取 X/Y 短轴，按 envImpact 分摊；N=1 冻结快照累加，尚非多箱上坡终态 |
| 接触速度 | 水平相对闭合决定有向动态力；跨帧速度归实体动态力容器，不存入 EntitySolutionResult |
| 静墙 | 不进实体 AABB pair；相位 5 保留静墙裁剪，Unity Dynamic 仍可能追加接触修正 |
| 容差 | 已有 slop；接触保持、释放阈值和多箱传播仍需后续评估 |

历史上采用 T+1 施力是为简化时序，不代表统一建模时不可重新评估。禁止无界递归、迭代中反复提交 Unity 位移，以及调试工具回写解算。

## 抖动、表现与后续边界（原 05–07）

- **V1：配置方案暂时解决。** 用户确认角色和箱子都启用 Rigidbody2D 插值后，当前推箱抖动消除；旧 P0 取证计划退出当前阻塞。插值解决显示问题的观察不等同于接触生命周期已被物理修复。
- **V2：未确认关闭。** 墙顶起跳停顿曾被观察到；查询与墙滑已改变，应先复测再安排修复。
- **F1：仅策略，未实现。** 物理提供只读接触与运动结果，表现层解析推动意图、有效推动和阻塞推动；不以 displacementOffset 或动态力 apply 直接表示“正在推”。
- **F2 / V3 / V4：仍待处理。** 斜坡多箱失败、静墙反馈与阻塞传播未随 F5 完成；新方向移交待办中的 F6/F2。
- **竖直环境速度：保留的旧规则。** 着地分支没有把 phyVSpeed 计入实体位移；平台 Y 位移不能替代它。平地、起跳首帧、斜坡与升降平台的组合应在统一运动建模时重新评估。
- **环境参数持续更新：未实现。** 属于新待办 F7，不回头扩大已完成 F5 的范围。
