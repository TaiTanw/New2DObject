# F_6：二维运动建模

2026-09-23 · 首轮结构评估。已正式进入评估，尚未修改实现；以下依据现码，不代表已完成场景复现或冻结方案。

目标：让水平、垂直运动使用一致的速度、位移和约束语义，为 F2 多箱上坡及 V3/V4 阻挡反馈提供基础。F5 的快照与环境边界可继续使用。

## 现有结构与确定缺口

| 位置 | 已实现 | 当前缺口 |
|---|---|---|
| `BasicEntity.SpeedCalculation / HUnderForce` | 相位 3 汇总速度；持续速度支持 Vector2 | 限时速度和动态力仍只累加 X；重力、跳跃单独写竖直标量。`HUnderForce` 实际同时写入 phyHSpeed/phyVSpeed，名称与职责不完全一致 |
| `BasicEntity.BuildMotionFrame` | 生成一次二维位移，预测与提交复用；平台位移单独相加 | 着地时舍去 phyVSpeed；把总 X 速度大小当作坡面切向速率，再单独叠加 verticalSpeed。不是统一的二维约束运算 |
| `Struct.EntityMotionFrame / PhysicalBoundingBox` | 只读基础位移、预测 AABB、接触偏置已分开 | 正式运行的快照只有 plannedWorldDelta；自由速度等分量是编辑器观测副本，不能直接作为新解算输入 |
| `PhysicsSolverMgr` | 预测 AABB 两两检测，X/Y 几何纠偏；有向接触力保留生命周期 | 速度传播只看 X，读取地面处理前的 GetPlanarVelocity，也不包含平台携带；与预测位移使用的运动含义不同 |
| `BasicEntity.DisplacementCorrection` | 相位 5 合并基础位移与偏置，再裁剪静墙并 MovePosition | 静墙结果不反馈本帧接触对；按 X 整轴裁剪，没有与地面、箱链共同求取允许运动 |

箱体已通过 `PhysicalBox.GeometricQuery` 取得地面法线，并使用同一个 `BuildMotionFrame` 沿坡运动。因此，多箱上坡并非完全缺少斜坡代码。现有 N=1 冻结预测、下帧生效的接触力与后置静墙裁剪，都可能影响箱链；**仅凭静态阅读，不能确认哪个是当前失败场景的主因**。

## 十分确定的事务

- [ ] 明确自由速度、地面处理后的运动、平台位移、接触纠偏及最终提交结果的含义，让预测与接触判断采用相容的数据。
- [ ] 补齐着地竖直外部速度的规则，覆盖向上、向下、起跳首帧和移动平台；不能简单把 phyVSpeed 无条件加回。
- [ ] 为二维接触明确法向相对运动和方向可移动性；将静态阻挡与箱链反馈纳入 F2、V3/V4 联合评估。
- [ ] 保留环境来源登记、累计速度和退出衰减的语义；角色的跳跃、松跳、墙跳与墙滑仍由角色层表达。
- [ ] 后续验收包含平地单箱/多箱、斜坡双箱/多箱、末箱抵墙和平台携带。角色与箱体均开启插值，分别观察请求位移和实际落点。

这是确定需要处理的事项，不是本轮已批准的实现步骤。

## 待定设计

| 待定点 | 需要先厘清 |
|---|---|
| 地面运动定义 | 输入速度代表世界 X 速率还是沿坡速率；外部速度如何受支撑限制、何时允许离地 |
| 数据结构与归属 | 标量来源是否保留、在哪里合成 Vector2；正式快照需要哪些解算输入，避免复制整套状态 |
| 接触解算方式 | 是否保留 T+1 施力、如何协调支撑与阻挡、是否需要有限迭代；不能只靠增大迭代次数解决 |
| 引擎职责 | 先以现有 Dynamic 混合模式评估；本轮不决定 F3 全 Kinematic 改造 |

建议下一轮先确定“自由速度 → 支撑处理 → 期望位移”的数学约定，再决定最小实现单元；暂不预铺新类、公式和步骤。
