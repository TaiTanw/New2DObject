## 1. 当前故障与证据

| 现象 | 现码证据 | 当前判断 |
|------|----------|----------|
| 贴 `wall (2)` 起跳，特定边缘位置在空中停顿一下 | `wall (2)` 位于 Layer 7；玩家 `groundLayer` 与 `wallLayer` 都是 Layer 6+7；地面/侧墙均使用 `distance=0` BoxCast；最终位置还会被 Dynamic 解算修正 | 高概率是墙顶边缘的接触分类切换，再叠加 Unity 角点修正；先补原始命中观测，不能先归因于跳跃 FSM |
| 斜坡上不能连续推动两个物块 | 接触对只做一次冻结快照遍历；求得偏置后不更新解算器内预测位置；`PhysicalBox` 不实现 `ICanMove`，因此第一只箱不能继续向第二只箱传播速度 | 已定位为接触链能力缺失，斜坡只是放大该问题 |
| 持续推动时轻微抖动 | 接触条件严格使用 `overlap > 0`；每次修正全部重叠；没有 skin、slop、接触保持；Dynamic 还可能进行第二次修正 | 已确认需要容差层，并继续观测双重权威的贡献 |

上述第一项仍是高概率诊断，不是最终定因。需要记录每帧原始命中 Collider、法线、命中点和 `engineCorrection` 后再改行为。

## 2. 已拍板事务

### D1. 当前继续使用 Dynamic 混合模式

- EPhy 负责速度、玩法语义、实体接触和期望位移。
- Unity 2D 暂时负责静态世界最终非穿透。
- 不以 `useFullKinematicContacts` 代替碰撞响应。
- 静态扫掠、残嵌恢复和接触稳定未闭环前，不切换全 Kinematic。

### D2. 物理根节点不旋转

- 推箱解算目前只处理平移，Rigidbody2D/Collider2D 所在根节点冻结旋转。
- 表现子节点可以独立旋转，但只能表达装饰效果，不能暗示真实碰撞朝向。

### D3. 引入 skin 与 slop

- `skin` 用于接触候选和速度约束的提前感知。
- `slop` 用于容忍极小穿入，避免每帧纠正浮点噪声。
- 不能简单地把预测 AABB 永久膨胀后再把膨胀量作为位移推出。
- 容差由解算器级配置统一持有，不散落在实体代码中。

推荐统一使用有符号间距：

```text
separation = centerDistance - (extentA + extentB)
separation < 0  表示穿入
separation = 0  表示理论接触
separation > 0  表示分离

contactCandidate = separation <= skin
penetration      = max(-separation, 0)
correction       = max(penetration - slop, 0) * correctionPercent
```

其中 `contactCandidate` 可参与法向速度判断；只有 `correction` 可以产生位置偏置。初始数值必须作为测试参数定标，不在算法方法内写死。

### D4. 两个及以上物块连续推动属于必需能力

- `N=1` 冻结快照不再视为可接受终态。
- 解算器应在自己的临时位置状态内迭代接触约束，最后一次性提交各实体总偏置。
- 迭代过程中不得反复调用 `MovePosition`，也不得让调试工具参与解算。
- 速度传播应改为相对法向速度语义，不能继续以“箱体是否实现 `ICanMove`”决定接触链是否中断。

### D5. 调试工具只读

- 调试数据只允许从运行逻辑复制到编辑器快照。
- 工具不能写回速度、位置、接触状态或解算配置。
- 后续历史记录使用定长环形缓冲，不在物理帧持续刷 `Debug.Log`。

## 3. 尚未拍板的实现细节

| 项目 | 候选方案 | 拍板条件 |
|------|----------|----------|
| Ground/Wall 是否拆成不同 Layer | 物理层拆分；或保持 Layer、改用目的明确的 ContactFilter2D | 先取得 `wall (2)` 边缘逐帧命中记录 |
| 接触保持是否需要跨帧缓存 | 先仅加 skin/slop；若候选仍反复切换，再加 pair cache 与释放阈值 | 静置与持续推动测试结果 |
| 位置约束迭代方式 | 解算器内 projected Gauss-Seidel，暂以少量固定迭代开始 | 双箱斜坡和三箱平地的顺序敏感性测试 |
| 是否关闭 Unity 的玩家–箱/箱–箱响应 | EPhy 稳定后按 Layer/Collider 关闭实体间重复响应，静态世界仍保留 | `engineCorrection` 证明 EPhy 已能独立维持实体接触 |
| skin/slop 初始值 | 世界单位固定值；或按最小 extents 比例计算 | 依据当前角色、箱体尺度和固定帧率定标 |

## 4. 开工顺序

### 阶段 A：建立四个固定复现场景

1. 玩家贴 `wall (2)`，在墙顶边缘连续起跳。
2. 平地连续推动两箱和三箱。
3. 现有约 15° 斜坡上连续推动两箱。
4. 单箱抵住静态墙后持续推动。

每个场景至少记录：`fixedTick`、FSM 状态、原始 ground/left/right 命中对象、法线、预测接触对、有符号间距、请求位移、最终位置和 `engineCorrection`。

### 阶段 B：先修墙顶边缘分类

1. 给只读快照补充原始几何命中信息。
2. 确认同一个 Collider 是否在相邻帧于 ground/wall 之间切换。
3. 将“感知查询”和“运动约束查询”继续分开；不得用扩大感知探针直接代替位移约束。
4. 若确认是角点法线不稳定，优先调整过滤与探针宽容区；不修改跳跃速度来掩盖停顿。

### 阶段 C：加入容差层

1. 新增解算器级 `contactSkin`、`penetrationSlop`、`correctionPercent` 配置。
2. 接触候选使用 skin，位置偏置使用扣除 slop 后的真实穿入。
3. 调试窗口同时显示 raw penetration 与 applied correction。
4. 先验证单箱平地、抵墙持续推动，再进入多箱测试。

### 阶段 D：升级接触链解算

1. 将预测样本复制为解算器本地 body state。
2. 每次约束迭代都更新本地预测中心，而不是重复使用原始 AABB。
3. 用相对法向速度判断接近/分离，并允许箱–箱传播运动意图。
4. 完成全部迭代后，向每个实体提交一次总 `displacementOffset` 和下一帧接触速度。
5. 检查遍历顺序反转后结果是否接近一致。

### 阶段 E：收紧混合权威

在前四阶段通过后，观察实体接触上的 `engineCorrection`。只有当其长期接近零，才测试关闭 Unity 的玩家–箱/箱–箱动力学响应；墙和地面的 Dynamic 兜底不在同一轮移除。

## 5. 验收条件

- `wall (2)` 边缘连续起跳不再出现超过一个 FixedUpdate 的非设计停顿。
- 平地三箱、斜坡两箱能够连续传递推动，箱体根节点角速度保持为零。
- 静置接触与持续推动时，接触候选不会逐帧高频成立/失效。
- 小于 slop 的穿入不产生位置修正；超过 slop 的修正量可在窗口中核对。
- 抵住无脚本静墙持续推动不穿墙，且不会因接触对偏置积累而逐步嵌入。
- 改变实体注册顺序后，多箱最终位置只允许出现容差范围内差异。

---

## 6. 本阶段不做

- 不切换全 Kinematic。
- 不把静态墙加入实体 AABB pair。
- 不实现箱体真实翻滚或角动力学。
- 不在修接触算法的同时批量重命名序列化数据类。
- 不通过调低跳跃速度、移动速度或扩大碰撞体掩盖边缘停顿。
