# 05 — 数据语义与调试约定

> 本文先统一“现名代表什么”，再决定是否批量重命名。当前不为改名破坏序列化或扩大推箱改动范围。
> 上级目录：[README.md](./README.md)

---

## 1. 当前混合物理边界

```text
EPhy 速度/玩法状态
    → predicted AABB / entity pair
    → desired delta + pair offset
    → Rigidbody2D.MovePosition(requestedTarget)
    → Unity Dynamic 静态世界约束
    → next tick actualPosition
```

当前职责：

| 范围 | 当前权威 | 目标 |
|------|----------|------|
| 玩家–箱、箱–箱推挤语义 | EPhy + Unity 残余接触 | EPhy 闭环后按 Layer 关闭重复引擎响应 |
| 实体–Ground/Wall 非穿透 | Unity Dynamic | 可长期保留；或待 EPhy 扫掠完整后再迁移 |
| 冰面、传送带、墙滑 | Unity 查询提供几何，EPhy 提供玩法效果 | 保持职责分离 |
| 箱体角运动 | 当前冻结物理根节点旋转 | 若需要真实翻滚，交给 Unity 或新增角解算，不做半套 |

箱子的表现子节点可以独立旋转，但碰撞根节点保持不转。该旋转只允许作为装饰表现；若图片朝向代表真实几何，必须与碰撞形状同步，不能继续使用此方案。

## 2. 数据类现名与目标语义

下表是迁移词典，不代表本轮立即重命名。

| 现名 | 当前真实语义 | 建议目标名 |
|------|--------------|------------|
| `PlayerPhysicsData` | 所有 `BasicEntity` 共用的运动状态，不只玩家 | `EntityMotionState` |
| `GeometryPhysicsData` | 帧初真实世界几何感知结果 | `EntityGeometryState` |
| `BasePhyFunData` | 地面/墙等表面职能引用与生命周期状态 | `SurfaceInteractionState` |
| `PhysicalFunctionData` | 角色专用的墙滑表面状态 | `CharacterSurfaceState` |
| `PhysicalBoundingBox` | 一个实体的预测世界 AABB 样本 | `PredictedAabbSample` |
| `EntityMotionFrame` | 相位 3 构建一次，预测和提交共用的只读基础运动快照 | 本阶段新增，见 `08` |
| `EntitySolutionResult` | 相位 4 产生、相位 5 消费的本帧接触解算结果；当前只有位置修正 | `EntityFramePhysicsResult` |

字段语义：

| 现字段 | 当前真实语义 | 建议目标名 / 处理 |
|--------|--------------|-------------------|
| `horizontalSpeed` | 主动水平速度 | `activeVelocityX` |
| `verticalSpeed` | 自研重力/跳跃产生的竖直速度 | `verticalVelocity` |
| `phyHSpeed`, `phyVSpeed` | 时间力、动态力和状态速度在相位 3 重建的被动速度 | 合并为 `externalVelocity` |
| `displacementBias` | 已停用草稿字段 | 验证无引用后删除 |
| `positionalEmbedding` | 已停用草稿字段 | 验证无引用后删除 |
| `nowtaijie` | 当前脚下命中的物理对象接口 | `groundBody` |
| `istop` | 是否顶头 | `isCeilingContact` |
| `canLeftWall`, `canRightWall` | 左/右命中的物理对象；可能为 null 的普通静墙 | `leftContactBody`, `rightContactBody` |
| `point` | 预测 AABB 世界中心 | `center` |
| `size` | 预测 AABB 半长宽 | `extents` |
| `displacementOffset` | 本帧接触对位置修正；不是速度、推箱状态或环境携带位移 | `contactCorrectionDelta` |

`secondOrderSpeed` 已删除。接触速度使用 `dynamicForceDic` 跨帧累计，不再属于 `EntitySolutionResult`。

迁移原则：先以文档和只读快照统一语义；待接触算法稳定后，再做一次机械重命名并同步所有文档，避免算法调试与大范围改名交织。

## 3. 几何查询语义

几何查询分成两类，不再混称为“碰撞检测”：

1. 感知查询：回答是否着地、贴墙、顶头，供 FSM 和表面职能使用。
2. 运动约束查询：沿本帧请求位移扫掠，回答最多允许移动多远。

当前 `groundV/leftV/rightV/upV + distance=0 BoxCast` 只适合第一类。它不能单独承担 Dynamic 被移除后的最终防穿透。

`SO_CPhysics` 中的探针尺寸与预制体 Transform/Collider 是多份几何数据源。后续应让运动约束直接从 Collider2D 取形状；手工探针只保留玩法宽容区。

## 4. 调试工具不可影响逻辑

硬约定：

- 调试窗口只读取快照，不调用 `AddForce`、`MovePosition` 或任何状态注册/注销方法。
- 调试数据不得参与接触判断、权重、速度和位移计算。
- 调试采样放在 `UNITY_EDITOR` 条件编译内；Player 构建不携带这些字段和列表。
- 窗口刷新频率与物理帧无关，以 `fixedTick` 标记数据所属物理帧。
- 不在每个 FixedUpdate 使用大量 `Debug.Log`；历史曲线后续使用定长环形缓冲。

当前快照字段：

| 字段 | 用途 |
|------|------|
| `actualPosition` | 新物理帧相位 3 采到的实际 Rigidbody2D 位置 |
| `requestedTarget` | 上一帧提交给 `MovePosition` 的目标 |
| `engineCorrection` | `actualPosition - requestedTarget`；观察 Unity 最终约束贡献 |
| `integratedVelocityDelta` | 总速度乘 fixedDeltaTime |
| `motionDelta` | 斜坡处理后的实体运动 |
| `platformDelta` | 平台补偿 |
| `plannedWorldDelta` | 从运行时运动快照复制的 `motionDelta + platformDelta`，预测和提交共用的基础位移 |
| `solverOffset` | 预测接触对贡献 |
| `unconstrainedDelta` | 静墙整轴裁剪前的总请求 |
| `requestedDelta` | 最终提交给 MovePosition 的位移 |
| `predictedCenter/extents` | 本帧预测 AABB |
| `DebugContacts` | 接触对双方、轴、原始/实际修正深度、闭合速度、施力方向、目标速度、法线、权重和偏置 |

## 5. 物理事实与表现状态

- 不因推箱动画需要而把 `displacementOffset` 放入 `PlayerPhysicsData`。
- 不新增 `isPushingAnimation` 一类表现命名字段。
- 管理器保存完整 contact pair 与 `source → receiver` 力关系；实体无需复制完整容器。
- 物理层后续提供本帧只读接触事实，表现层结合动作输入、着地和最终位移解析动画。
- 推动接触、速度传递、有效推动和阻塞推动不是同一个状态，不能用单一偏置或动态力布尔替代。

完整策略见 [07-推箱交互事实与表现状态.md](./07-推箱交互事实与表现状态.md)。

## 6. 下一步数据整理顺序

1. 先关闭 [06](./06-已拍板事务与开工顺序.md) 的持续推箱 P0 抖动，确认 `engineCorrection` 与 pair/link 开关来源。
2. 完成 contact skin/释放阈值，再补静态世界沿 `requestedDelta` 的 Cast。
3. 升级多箱迭代并明确方向自由度/最终运动结果。
4. 按 [07](./07-推箱交互事实与表现状态.md) 增加运行时只读接触摘要，再接入推箱动画。
5. 分离 `Ground` 与 `Pushable` Layer 或能力语义，建立可配置的碰撞权威边界。
6. 删除两个已停用草稿字段，集中执行数据类/字段机械重命名。
