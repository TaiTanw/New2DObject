## 3. AABB 重叠与挤出（位移侧，解算器内）

注释中的算法（与文档 02 一致）：

```text
v1 = a.point - b.point          // 方位（后续判谁推谁）
v2 = (|v1.x|, |v1.y|)           // 中心距轴分量
v3 = a.size + b.size            // 注意：须与 size 约定一致（半宽还是全宽）
v4 = v3 - v2                    // 各轴重叠深度
重叠 ⇔ v4.x > 0 && v4.y > 0
挤出轴 = v4 较短轴
权重   = envImpact_a / (envImpact_a + envImpact_b)
写入双方 displacementBias（本帧 Move 使用）
```

## 4. 速度施力算法（实体接触 · 收束）

### 4.1 关键改动：用「移动能力」判断能否速度施力

```text
仅当施力方 is ICanMove 时，才进入「接触速度施力」分支
否则：只做位移挤出（bias），不写 secondaryPressure
```

**评估：**

| | 说明 |
|---|---|
| 相对「相对速度阈值分档」 | 更简单，与冰面已用 `ICanMove`/`Mobility` 一致 |
| 语义 | 「会主动移动的实体」才把运动意图打成接触冲量；纯被动箱主要靠 bias 被挤走 |
| 多层箱 | 箱若 **未** 实现 `ICanMove`，箱→箱主要靠 N=1 bias 传挤出，**不靠**速度施力链（可接受的 MVP 简化） |
| 风险 | 若希望箱撞箱也产生冲量手感，需给箱加 `ICanMove` 或另设 `IContactForceSource`（未决） |

`Mobility` 本身更适合作为 **平衡速/力幅参考**（冰面已有先例），「能否施力」用接口存在性即可；数值用于算多大。

### 4.2 施力速度从哪来（注释收束）

注释要点：

1. 用施力物体的 **被动速度类叠加速度** 作为施力叠加速度来源，再乘双方 `envImpact` 得到对受力方的影响。  
2. **不要用状态速度（传送带）** 当瞬间接触冲量参数：清空后还会被环境复原，瞬间接触语义不稳。  
3. 适合计入的叠加：限时速度、`dynamicForce` 且类型合适者（注释写：时间力 + `fadeAway` 类动态力可致叠加；具体枚举以落地为准）。  
4. 写入 **专属容器**（`secondaryPressureDic`），每次解算清空再写；**下帧**正式速度相合并（T+1）。

示意：

```text
if (重叠 && a 或 b 为 ICanMove):
  pusher, pushee = 按 v1 方位 + 速度朝向判定（谁在挤入）
  if pusher is ICanMove:
    impulseSpeed = 抽取(pusher 被动可叠加速度)   // 不含状态速度
    按 envImpact 分配/缩放 → 写入 pushee.secondaryPressureDic
    // 可选：削弱 pusher 向内速度意图（本帧或 T+1，见 99）
本帧不把 secondaryPressure 并进 v_pre 再预测（禁止递归）
```

### 4.3 与位移挤出的关系

| | 本帧 | 下帧 |
|---|---|---|
| bias（挤出） | 必用 | — |
| secondaryPressure（速度施力） | 只写意图 | 速度相入账 |

小速度/无 `ICanMove`：偏 **只 bias**。  
有 `ICanMove` 且构成挤压：bias +（T+1）速度施力。

## 5. 评估：当前讨论是否合理

**合理且与总设计对齐的部分**

- 相位 4 管理器统一 pair，冻 `projectingArray` 快照 → 顺序公平。  
- `ICanMove` 门控速度施力 → 降低分档复杂度。  
- 专属容器 + T+1 → 避免预测世界同帧改速递归。  
- 不存长期施力引用 → 每帧重算，职能可退化。  
- 状态速度排除出瞬间冲量参数 → 判断正确。  

**需在实现时盯紧的点**

1. `size` 是半伸长还是全宽，必须与 `v3=a.size+b.size` 公式一致（见 99）。  
2. `displacementBias` 现为 `float`，轴向挤出需要 **按轴分量**（`Vector2` 或拆字段）。  
3. `PositionPrediction` 尚未看到向 `projectingArray` 注册的实现；需在解算前清空数组再全员上报。  
4. 实体注释里的「撞墙制零」应留在位移/相位 1，**不要**进可推 AABB 解算器（见 03）。  
5. 旧相位 6 `SecondOrderPhyFun` 推箱与相位 4 解算双轨时会再抖，迁移后删除。

```text
ContactForSolution:                    // 相位4，数组已由相位3末上报
  clear 各实体本帧 bias / secondaryPressure 意图
  for i, j in pairs(projectingArray):
    if not AABBOverlap(a,b): continue
    axis, depth, side = ShortAxisSeparation(...)
    WriteBias(a,b, weights, axis, depth)     // 本帧
    ResolvePusherPushee(a,b, v1, velocities)

      WriteSecondaryPressure(pushee, from pusher passive stack)  // T+1
  // 不重跑预测，不改 v_pre
```
