# 功能与漏洞安排

**何时读：** 出现漏洞或增减功能，需要工程安排；位于「开发策略 / 询问代码结构」与「已明确开工」之间。

本轮只回答两件事：

- 当前是什么问题
- 怎么分类（字母、序号、0.1 开工条目）

具体问题落到 [SKILL.md 第 6 节](../SKILL.md) 填写框里的 **事务表**，不写进 skill 正文，也不在对话里展开成长篇题述。事务表未填则先问文件名。表格形态见 [docs-and-artifacts.md](docs-and-artifacts.md)。

排完一条可验的最小开工单位后，若用户明确开工，再转入 [start-modes.md](start-modes.md)。尚未收敛到三类之一时，先核对需求，不准写代码。

## 分类


| 字母  | 含义                | 可用其它字母             |
| --- | ----------------- | ------------------ |
| `V` | 漏洞（vulnerability） | 可以。新字母先在事务文档里声明再使用 |
| `F` | 功能（Function）      | 同上                 |


编号：

- `V_2`：第 2 个漏洞
- `V_2.3`：漏洞 2 的第 3 条实际开工。`2` 是第几个问题，`.3` 是该问题下第几条开工
- 一条实际开工 = **最小逻辑闭环** + **可验的最小实现**，计作一个 `0.1` 单位。表里的 `0.1`、`0.2` 对应 `.1`、`.2`

未拆到可验的 0.1 之前，只登记问题，不进入开工三类。

## 对话里怎么答

短答即可，例如：当前是 `V_2`（一句话问题名），本轮可验单位建议 `V_2.1`。正文用填写框里的事务表路径；不要把路径复制进其它 reference。
