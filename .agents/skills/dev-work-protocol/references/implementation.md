# 代码实现

**何时读：** 已经分类开工，开始写代码时。

## 1. 用户忽略代码

用户不在乎代码怎么写，只在乎能不能用。

落在忽略范围内的代码：

- 仍必须停在本轮范围里，不能顺便改范围外。
- 不为「写得更好看」增加结构。
- 不主动做高等级代码解释。
- 注释保持能编译、能读完流程即可，不要按下面第 2 节展开。

范围由用户维护。当前为空则：若本轮是 **流程验证**，整次改动都按忽略代码处理；其它模式不要自行扩大忽略范围。

```text
涉及unity编辑器的调试（尽可能让实际功能与编辑器调试区分在不同的脚本文件，功能区只保留调用编辑器的窄口，或者干脆直接编辑器反射获取数据）
调试主要是让AI阅读和排查

```

## 2. 注释情况

当这部分代码 **不在** 用户忽略代码范围时适用。

### 运算和调用

尽可能清楚说明步骤在做什么。

- 逻辑分支语句一定要说明到底是满足什么条件。
- 哪些是安全做法（判空、判零等），哪些是实际逻辑，必须分开写，不要混成一句「防御一下」。

```csharp
// 安全：来源已销毁时不能再读能力，直接视为无效果。
if (source == null) return;

// 实际逻辑：最后一个接入依据移除后才撤销效果，避免区域里还有另一个 Collider 重叠时提前退出。
if (binding.access == 0) Detach(source);
```

### 类和结构体（三杠注释）

先具体通俗说明这数据结构是做什么的，再抽象说明它的层级职能。

- 具体层面尽可能清楚，文字可膨胀，甚至举例均可。
- 抽象部分要精炼严谨。
- 顺序固定：**先具体，再抽象**。

```csharp
/// <summary>
/// 实体相位 2 从当前脚下表面采到的一组数：地面会不会把人变慢、跳得高不高、
/// 以及这块平台本帧已经走了多远。例如踩传送带时，位移走 platformDelta，
/// 而不是把传送带速度再写进动态力容器。
/// 职能：执行层只读采样结果；不拥有跨帧力/速度，也不表示几何命中本身。
/// </summary>
```

现码里 `EntityEnvironmentContext`、`PresentationLayer` 的三杠注释接近此顺序，新类型按这个写，不要抄成空的「实体基类」式标题。

## 其它实现约束

- 遵守 [design-principles.md](design-principles.md) 的单向管线和层级边界。
- 不在实现时批量重命名序列化字段或数据类，除非本轮任务就是改名。
- 调试或编辑器工具默认只读，不写回运行时解算数据。
