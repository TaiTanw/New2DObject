# 原则展开

**何时读：** 用户讨论开发策略，或询问代码结构。

上半是可复用原则。下半是当前仓库对照，暂按现有文档和代码结构书写，随后由用户核对。不要在此写入专题算法（接触解算、推箱稳定化等）。

## 可复用原则

1. **逻辑脱离宿主生命周期**  
   玩法逻辑用纯类型表达。宿主（此处为 `MonoBehaviour`）只做容器、调度、生命周期和场景引用。

2. **单向数据管线**  
   意图从上往下流：外来输入 → 实际类别调度 → 行为策略 → 执行 → 表现。下层只读快照，禁止回写上层。上一层不宜知晓下一层内部有什么。

3. **行为 vs 执行**  
   行为层只决定「能否做 / 做什么」。执行层只根据已过滤意图计算速度、位移或其它结果。

4. **感知 vs 职能**  
   几何/碰撞查询只描述「碰到了什么」。领域效果走接口登记，不把效果写进探测代码。

5. **环境效果登记/解除**  
   进入与退出时注册或撤销效果，避免每帧按场景类型硬编码。

6. **接口扩展**  
   新类型优先实现已有能力接口，少改底层查询与时序骨架。

7. **角色对象四层组装**  
   一个实际的角色对象（玩家或怪物：有具体行为）由下面四层组成。一层对应一个挂载的自定义脚本；该脚本管理同层级的其它脚本。因单向数据流，上一层不宜知晓下一层内部有什么。一层内若有多种效果组织，不宜膨胀该脚本，而是在对应层安排数据组织。

   1. **实际类别** — 回答此角色是谁。例如玩家的 `Player` 脚本：统一调度，找到其它组件并安排初始化，接入玩家独有的输入系统。其它角色声明专属脚本，按需关联 AI 等组件。
   2. **行为策略** — 回答具体有哪些行为。玩家侧处理输入传来的数据，怪物侧接入 AI。输入绑定不算本层：它是输入管理器处理的外来数据，不是单独一个自管脚本。
   3. **执行** — 回答实际会产生的效果，例如物理、伤害等。
   4. **表现** — 接收上层数据，安排动画表现。

8. **配置外置**  
   检测层、尺寸、开关等走配置资产，不散落在算法方法里写死。

策略讨论时先用这 8 条判断越界，再用下面的对照落到本仓库符号。

## 当前仓库对照（待核对）

来源：总览、文档索引、结构图以 [SKILL.md 第 6 节](../SKILL.md) 填写框为准，再对照现码。不要把专题问题文档路径写进本文件。

### 管线

```text
InputControlMgr → PlayerInputData          （外来数据，不是角色上的一层）
    → Player                               （实际类别：调度 / 初始化）
        → PlayerStateMachine               （行为策略：处理传入数据）
            → CharacterPhysics / BasicEntity  （执行：物理等效果）
                → PresentationLayer        （表现：只读快照）
```

- 行为策略 **不写** `Rigidbody2D`、不算重力。
- `PresentationLayer` **不回写** 逻辑或物理。
- 只读包装（`ReadOnly_ActionData`、`ReadOnly_GeometryPhysicsData`、`ReadOnly_PlayerPhysicsData`）是边界，不是装饰。
- `InputControlMgr` 属于公共调度，不是角色对象的第五层。

### 层级

公共调度（不算角色四层）：`Main`、`MonoPublicMgr`、各 Mgr — 注入资源、按槽驱动回调。

| 角色层 | 现码落点 | 只允许做什么 |
|--------|----------|----------------|
| 实际类别 | `Player`（其它角色尚未普遍有专属编排脚本） | 回答是谁；找齐组件、初始化、接入该角色需要的外来输入 |
| 行为策略 | `PlayerStateMachine` 及状态类 | 回答有哪些行为；处理输入/AI 传来的数据，写出意图与瞬时事件 |
| 执行 | `CharacterPhysics` / `BasicEntity`；环境源 | 回答产生什么效果：几何、速度、位移、环境登记、伤害等 |
| 表现 | `PresentationLayer` | 接收上层数据，安排动画与朝向 |

上一层不宜知晓下一层内部有什么。一层内多种效果走该层的数据组织，不把编排脚本或表现脚本膨胀成全能类。跨层「为了方便」互改字段视为越界。

### 环境职能（结构级，不是专题算法）

- 几何身份与环境能力分开：无脚本表面仍可阻挡；能力缺席表示没有该效果。
- 实体持有关系（`IEnvironmentReceiver` / `EntityEnvironmentContext`）；源端只保留清理用反向索引。
- `BasicPhysicalObject` 是兼容入口，不是能力接口的必要父类。
- 新环境类型优先加能力接口，不先改几何查询，也不先加全局环境管理器。

### 物理时序骨架

`MonoPublicMgr.actionsLen` 按槽位 0→后顺序调用。当前含义（对照现码，待核对）：

| 槽 | 现含义 |
|----|--------|
| 0 | 平台等自运动 |
| 1 | 真实几何查询 |
| 2 | 职能/环境核对与采样 |
| 3 | 速度与本帧运动快照 |
| 4 | 位移修正（含实体接触等后续专题，此处不展开） |
| 5 | 提交位移 / 收尾观测 |

策略问题先问：改动落在哪一层、哪个槽、是否破坏单向管线。不要在本文件展开槽 4 的专题算法。
